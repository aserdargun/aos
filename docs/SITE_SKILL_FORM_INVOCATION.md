# W3 typed S1 form invocation — scheduler opt-in

`aos.site_skill_form_invocation` compiles one selected S1 skill variation case into a canonical invocation pin for the existing `RemoteFormOperator`. It binds the immutable skill and variation plan, private case-input identity, exact registered profile/task, selected parameter-to-field map, exact form plan and state-readback plan. The entry origin must be synthetic `.invalid`, and the state plan must declare its submitted-field marker.

The only accepted stages are `open_entry`, `read_state_before`, `fill_form`, `submit_form`, `read_receipt`, and `read_state_after`, in that order. This fixed form template does not execute the skill draft's symbolic `step_keys`; no model output supplies stages, tools, URLs, or retries. The form operator checks the exact artifact hash and its current task/form/state hashes before creating a run. It writes the invocation hash into the run state before the first action; each existing scheduler action still requires its own fresh approval and the existing one-POST request permit remains in force.

The plan is an opt-in direct `scripts/serve_desktop.py` input. Provide `--remote-form-skill-plan-file` and its SHA-256, `--remote-form-skill-case-inputs-file` and its SHA-256, `--remote-form-skill-field-bindings-file` and its SHA-256, `--remote-form-skill-case-key`, and `--remote-form-skill-invocation-sha256` alongside the exact form/state plan and private form value. All source files must be canonical, owner-only files beneath ignored `data/`; public target grants and cookies are rejected for this synthetic invocation. The expected invocation hash is `digest(compile_site_skill_form_invocation(...))` using the same exact registered profile, skill store and selected source files. Direct CLI admission does not set up `.invalid` DNS/TLS fixtures and is not transport evidence.

The scheduler revalidates all source files before job creation, before initial run binding, and before each form action. `aos.site_skill_form_invocation_audit` recompiles the current sources and composes the existing six-stage form-source auditor against the same frozen SQLite snapshot. It requires 32 exact ordered typed state snapshots (initial CREATED, six fixed five-phase transitions, terminal SUCCEEDED), the invocation hash from the initial state through every state, six consumed authenticated-human approvals tied to DECIDE/EXECUTE states, one submit, and ordered independent receipt/state readbacks. The report claim is narrowly `fixed_template_invocation_execution_verified`; its `skill_executed`, symbolic-step execution, site outcome, review, activation and training flags remain false. It does not run the skill draft's symbolic `step_keys`.

The explicit `./scripts/aos-v1 start --owned-synthetic-form-invocation` opt-in provisions private canonical sources and an owned loopback TLS fixture under one fresh managed session. Tasks exposes the single-use `browser_remote_form` task and a read-only invocation audit; the backend rechecks the private source manifest on every manual audit request. This fixture is an owned test endpoint, not `.invalid` public DNS, a real website, or a target account. The fixed template does not execute sorted symbolic `skill.step_keys`; `skill_executed`, site outcome, review, activation and training remain unproven. The isolated real-Decider supervisor/backend/Tasks run on a private ephemeral UI listener passes six approvals, audit, reuse rejection, clean backend shutdown and fixture-port release. Public `start` port-8765 reservation and launch remain unit-covered only and are not part of that end-to-end run. Reviewer approval, target-account outcome, activation/rollback, and W1–W6 acceptance remain open.

The canonical invocation contract and synthetic-only example are [schema](../schemas/site_skill_form_invocation.schema.json) and [fixture](../examples/site_skill_form_invocation.json); the post-run audit uses its own [schema](../schemas/site_skill_form_invocation_audit.schema.json) and [synthetic fixture](../examples/site_skill_form_invocation_audit.json). The opt-in owned real-Decider relay test is `tests.test_web_https_relay.WebHTTPSRelayTests.test_real_decider_scheduled_typed_form_invocation_audit`; it requires `AOS_DESKTOP_TESTS=1`, `AOS_HTTPS_RELAY_TESTS=1`, and `AOS_FORM_INVOCATION_REAL_DECIDER_TESTS=1`.
