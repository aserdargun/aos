# Opt-in incremental synthetic learning metadata

`aos.learning_event_stream` is an explicit, bounded polling CLI for an **already-running synthetic task**, with a separate opt-in scheduler hook described below. Each poll audits a read-only source snapshot, projects only pinned successful model calls, and appends role-separated metadata to a separate private SQLite store. It does not collect from a real site, create labels/datasets/skills, or authorize training.

```sh
.venv/bin/python -m aos.learning_event_stream \
  --database /path/to/private-trajectory.sqlite --run-id RUN_ID \
  --roles both --outbox-dir /path/to/private-learning-stream \
  --watch-seconds 60 --interval-seconds 1
```

`--roles system1` or `--roles system2` selects one role. Without `--watch-seconds`, the CLI polls once. The watcher stops within 300 seconds and 1200 polls; an external caller must explicitly start another watch. The report is canonical JSON with counts and hashes, not raw event content.

The separate `database/learning_migrations/0001_incremental_metadata.sql` and append-only `database/learning_migrations/0002_downstream_metadata.sql` own the outbox format; they do not migrate the trajectory DB. A valid v1 outbox is upgraded in place without changing its existing entries; a v1 entry with invalid shape, canonical bytes, or content hash is rejected before migration. The output directory and DB must be owner-only (0700/0600). A source DB must be owner-only 0600 and single-link. The first poll binds the outbox to the source path/device/inode and exact audited schema, and binds each selected run to its task, synthetic policy and pinned deployment snapshot. Polls are transactionally appended and idempotent after restart; a replaced source, changed run binding, missing prior event, changed source row, corrupt outbox, or incompatible schema fails closed. There is no automatic repair or provenance promotion. Keep the store private because IDs and hashes remain sensitive metadata.

An optional scheduler hook is available only when the console server is explicitly launched with `--synthetic-learning-stream-dir /path/to/private-learning-stream` **outside the agent workspace** and an authenticated fixed-task Start request includes `"learning_metadata": true`. Default Start requests and existing managed sessions remain unchanged. The scheduler verifies the configured trajectory matches its owned store, polls synchronously after a committed decision and immediately before its action approval, and once after that run invocation settles. It never snapshots while its trajectory connection has an active write transaction or launches a concurrent polling writer. The source auditor has a 10-second deadline and bounded snapshot size, while the outbox has a 2-second SQLite busy timeout; this is not a strict total wall-clock guarantee. Measured `duration_ms` appears in authenticated `/api/tasks/learning/{job_id}` and in each job's `/api/tasks` learning status. Opt-in may add that latency at each approval and at settlement.

A new managed pilot session may enable the capability with `./scripts/aos-v1 start --synthetic-learning`; this points the separate outbox to that session's private `learning-stream/` directory. It can be combined with `--synthetic-staging` after an existing session is safely stopped. The Tasks UI checkbox remains off by default and applies only to the one started synthetic task. Neither flag hot-upgrades an existing managed session.

The opt-in event is durable in the trajectory, and each successful/failed poll writes a metadata-only audit event. Outbox errors stop automatic polling for that job and surface `failed` (or `failed_unpersisted` while the process remains alive if audit-event persistence itself fails); they never convert a verified task outcome or approval into a collection-success claim. A process crash or restart with an opt-in but no settled poll is `recovery_required` on historical job inspection; the explicit CLI above can re-poll the exact run after operator inspection. This is not automatic crash replay. Fixture-model tasks produce zero S1/S2 model entries, not fake calls.

An S1 `call_observed` entry needs an actual pinned successful S1 call joined to a decision; a later independently validated verification adds a distinct `verification_linked` entry. An S2 `call_observed` entry needs an actual pinned successful Bonsai call. For a synthetic canvas scene bound to that call, a later independently validated Decider action/outcome also adds a separate S2 `downstream_verification_linked` entry with the scene observation and verification IDs. It means the Bonsai scene preceded a verified downstream S1 outcome, **not** that Bonsai's scene or diagnosis was independently correct. Missing Bonsai calls or a valid scene produce no S2 link; downstream S1 verification never becomes S2 gold. The new link uses derivation v2; earlier v1 entry IDs stay stable. Each entry carries source row and snapshot fingerprints but never a request, response, screenshot, DOM payload, secret, or raw trajectory. Every entry remains `synthetic=true`, `collection_authorized=false`, and `training_ready=false`.

The canonical contracts are `schemas/learning_event_stream_entry.schema.json` and `schemas/learning_event_stream_report.schema.json`; `examples/learning_event_stream.json` uses explicitly synthetic placeholder fingerprints. Focused tests exercise polling during a synthetic writer, role separation, late verification, S2 downstream linking, v1 migration, restart/dedup, source drift, unsafe files and schema checks. Real-site rights, reviewed labels, an authorized live collector, held-out datasets and fine-tuning remain separate W1/W4–W6 gates.
